# Markdown Format

Приводит существующий Markdown-документ к валидной разметке CommonMark/GFM,
не меняя его смысл и не выдумывая недостающий контент.

## Принципы

1. **Смысл не менять.** Правится только разметка. Формулировки, порядок блоков,
   числа и значения сохраняются дословно.
2. **Контент не выдумывать.** Если раздел потерян (пропущен номер, обрыв файла) —
   оставить как есть и явно сообщить пользователю, а не сочинить.
3. **Нумерация — источник истины.** Если из структуры явно следует пропущенный
   подзаголовок (например `9.1`, `9.3`, `9.4` вокруг блока кода), восстановить
   его и **отметить в отчёте**, что заголовок добавлен.
4. **Минимальный дифф.** Правки точечные; не переписывать абзацы целиком.

## Порядок работы

1. Прочитать файл целиком.
2. Построить карту блоков: заголовки, fence-блоки, списки, таблицы.
3. Применить правила ниже.
4. Проверить результат автоматически (см. «Проверка»).

## Правила

### Fenced code blocks

- **Каждый** блок кода оборачивается в ``` с языком: `typescript`, `json`, `sql`,
  `bash`, `text` (для ASCII-схем и деревьев), `html`.
- Fence-открыватель и закрыватель — на отдельных строках, fence 0-3 пробела
  отступ, не более 3.
- Внутренний отступ кода внутри fence сохраняется как есть, но единообразно
  (один уровень, 2 или 4 пробела — не смешивать в одном блоке).
- Незакрытый fence в исходнике — главный источник «потерянных» заголовков:
  найти, где fence должен закрываться, и разбить слипшийся блок на части.

### Заголовки

- Ровно один `#` (H1) — заголовок документа. Второй `#` превращается в H2,
  либо, если это имя файла-спецификации, в блок-цитату под H1.
- Иерархия без пропусков: `#` → `##` → `###` → `####`.
- Перед заголовком — пустая строка, после — пустая строка.
- Нумерованные разделы (`## 7. ...`, `### 7.1. ...`) сохраняют свои номера.

### Списки

- Элемент списка начинается с `-`; маркер не выравнивается «лесенкой».
- **Список, отступ которого ≥ 4 пробелов без fence, Markdown считает блоком кода.**
  Снимать отступы: `- пункт` на нулевом уровне, 2 пробела для вложенности.
- Перед списком и после — пустая строка.
- Для структур вида «Содержимое: / Логика:» использовать подзаголовок `####`
  либо жирный термин-маркер, а не пустые строки как разделитель.
- Многострочный пункт: первая строка с маркером, продолжение с отступом 2–3
  пробела.

### ASCII-схемы и деревья

- Дерево каталогов и бло-схема с псевдографикой (`┌ ─ │ └ ├`) оборачиваются в
  ```text и выравниваются по правому краю рамки.
- Если рамка «едет» (строка шире/уже границ), пересобрать ширину по самой
  длинной внутренней строке.

### Таблицы GFM

- Таблица = строка-шапка, строка разделителя `| --- |`, тело.
- Выравнивание задаётся в разделителе: `:---` слева, `---:` справа, `:---:`
  по центру.
- Выравнивать колонки по ширине содержимого (читаемость в исходнике).
- Одиночная ячейка/строка без разделителя — это не таблица; переводить в список.

### Прочее

- Frontmatter, если есть, — первым, между `---`, с валидным YAML.
- `---` между разделами — горизонтальный разделитель, пустые строки вокруг.
- Типографика: `…` вместо `...`, `—` вместо `-` в прозаических перечислениях,
  неразрывные пробелы в `130 000 ₽`.
- Хвост файла, оборванный на полуслове, — не «дополнять», а оставить и
  сообщить пользователю.

## Проверка

После правок прогнать:

- баланс fence: число строк, начинающихся с ``` , должно быть чётным;
- ровно один H1, нет пропусков уровней заголовков;
- нет строк с отступом ≥ 4 пробелов вне fence (кроме отступов в списках
  уровня 2);
- каждый fence имеет непустой info string.

## Формат отчёта

Коротко перечислить: что поправлено (счётчиком), что добавлено как
восстановленное, какие пробелы в исходнике остались (пропущенные разделы,
обрезанный хвост) и требуют решения пользователя.
